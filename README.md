# 블로그 NAVI v1.4 — 근거 기반 자동 수정·재검증

## 변경사항
- **공식자료·근거 검증** 메뉴에 `⑤ AI 자동 수정 · 문장 비교 · 수정 이력` 추가
- 기존 검증 리포트와 등록된 공식 원문 PDF/HTML/TXT를 입력으로 AI 수정안 생성
- 주장별 수정 전/후, 수정 이유, 문서명, 원문 인용, 페이지 정보 표시
- 전체 원고 줄 단위 변경 비교(unified diff) 및 최종 수정본 직접 편집
- 담당자 확인을 눌러야 수정 원고 반영 가능. 변경 전 원문과 수정 이력 DB 보존, 이전 원고 다운로드/복구
- 수정 원고 반영 시 항상 `검수 대기`; 현재 원고로 AI 근거 대조 다시 실행해야 승인 가능
- AI 검증 결과의 `불일치`, `근거부족`, 검증된 인용 확인 실패는 모두 승인 차단
- 기존 메뉴 및 API 키 시크릿 이름 유지. 새 `revision_audit` DB 테이블 자동 생성.

## 설치
1. **현재 앱의 `설정·백업`에서 백업 ZIP을 먼저 내려받으세요.** Streamlit Community Cloud의 로컬 DB는 영구 저장되지 않습니다.
2. 이 ZIP의 `blog_navi_v1_4/app.py`와 `blog_navi_v1_4/requirements.txt` 파일을 GitHub 저장소 최상위에 업로드(기존 파일 교체)하세요. 폴더 자체를 앱의 루트로 올리는 방식은 기존 배포 설정과 다를 수 있습니다.
3. GitHub `Commit changes` → Streamlit 재배포 → Ctrl+Shift+R.
4. 기존 Secrets: `BLOG_NAVI_PASSWORD`, `OPENAI_API_KEY` 그대로 사용합니다.

## 사용 순서
1. `공식자료·근거 검증` → 원고 선택 → 교육부/대교협/대학 공식 원문 자동수집 또는 PDF/TXT 등록
2. `④ AI 근거 대조` 실행. 보고서의 주장별 판정과 인용 원문 확인
3. `⑤ AI 자동 수정` 클릭. 수정 전후 표, 수정 이유, 출처·페이지·인용문 검토
4. 제안에 잘못된 수치/근거가 있으면 직접 편집. 확인 체크 → **검토한 수정안 원고에 반영**
5. 같은 메뉴에서 **④ AI 근거 대조 다시 실행**. 검증 결과의 `불일치`·`근거부족` 문제를 해소하고 원문을 직접 점검
6. `원고 편집·검수`에서 수동 사실확인 기록(기관명, 문서명, URL, 페이지, 확인한 수치/규정, 확인일)을 남기고 상태를 `승인`으로 변경
7. `예약 발행 지원`에서 게시용 TXT/HTML을 다운로드하여 네이버/티스토리 편집기에 직접 등록

## 중요 제한
- AI 원문 인용은 원문 텍스트에서 단순 문자열로 대조합니다. 인용과 페이지 정보가 정확하다는 보장은 없으며 PDF 스캔/표/레이아웃은 오판정할 수 있습니다.
- AI는 등록된 **최대 4개 문서의 앞 18,000자씩** 참조합니다. 해당 범위 밖의 내용은 `근거부족`으로 남을 수 있습니다.
- 개별 대학 전형은 해당 학년도 최신 공식 모집요강과 시행계획을 구분하여 확인하세요.
- 외부 OpenAI API 호출에는 토큰별 사용료가 발생합니다. 외부 사이트 원문이 프롬프트로 전달되므로 민감한 정보는 등록하지 마세요.
- *공식 PDF 자동수집 기능은 사이트 구조에 따라 작동하지 않을 수 있습니다.* 이 경우 PDF 수동 업로드를 사용하세요.
- 자동 게시가 아니라 **검수 후 수동 예약 발행 지원**입니다.
- `설정·백업`의 ZIP에는 수정 이력도 포함되나, 현재 앱의 복원 메뉴는 `posts.json`만 병합합니다. 전체 데이터의 완전 복원 기능은 아직 없습니다. 운영 DB를 장기 보존하려면 외부 영속 DB가 필요합니다.

## 개발 검사
Python 문법 검사 및 DB 승인 차단 테스트를 수행했습니다. 실제 Streamlit UI·유료 API·교육부 URL 통합 테스트는 배포 환경에서 확인해야 합니다.
